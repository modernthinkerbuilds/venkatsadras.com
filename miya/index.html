The agent I built · its team

Miya

My personal AI agent. One place to ask about my training, my evenings, our weekends and where we eat, with five specialists behind it.

Live since Jun 8, 2026

What I ask Miya

I don't pick an agent. I ask Miya, and the ask goes to whoever owns it.

  • Kobe answers

    “Where am I this week?”

    Answered in code from the watch data. No model, same answer every time.

  • Fraser answers

    “Design me a session for tomorrow.”

    Written by a model, then checked against a 10-point contract in code before I see it.

  • Huberman answers

    “Give me a cooldown.”

    Built from a 25-drill library for the day I actually had. It also shows up on its own every evening.

  • Genie answers

    “What's on this weekend?”

    Local events from 122 sources, planned around what we've already decided.

  • Bourdain answers

    “Where do we eat?”

    On its own door for now, being tested on the harness. It joins Miya when it passes.

  • Miya answers

    Anything else

    No rule claims it, so Miya's model takes it, asks the specialists for facts, and answers in one voice.

The problem

I didn't want six apps in my pocket. I wanted one agent I could ask anything, and one that wouldn't confidently tell me something false about my own life.

Why I have it

Miya is the front desk and the editor. It sends each message to the specialist that knows the answer, and runs seven checks against the facts on record before that answer reaches me.

What it does

  • Routes every message: 16 rules in code answer the asks they recognize, most of them without a model, and Miya's model handles everything else.
  • Pulls facts from the specialists and answers in one voice.
  • Sends a morning brief, and one line at 08:15 when something in the system is broken.

Where it helped

  • After the rebuild, I replayed 126 real messages from my own history. Internal-voice leaks, the failure I had been patching by hand, went to 0%; about one reply in twenty (4.8%) had a contradiction the validator caught and corrected.
  • Rahat's decision ledger has logged 7,408 decisions since May 8, each with the agent, the rule, the latency and the cost.
  • On its first day on the new platform it surfaced a bug that flipped “ahead” and “behind”. It's now pinned by a test.

The 126-message replay and the 86-ask eval sets are different tests: the replay is Miya's own history; the eval sets are Bourdain's and Genie's asks.

How it works

The steps, in the order a message meets them. The names are the real components in the code.

  1. I askOne message to Miya, on Telegram.
  2. The rules16 rules in code, checked in order. The first to claim the message answers it, most without a model.
  3. Miya's modelTakes what no rule claims, and asks the specialists for facts.
  4. One voiceThe reply is put in one voice, unless it's an exact number from code.
  5. ValidatorSeven checks against the facts on record. Rewrites the reply before it sends.
  6. RecordedEvery step lands in the decision ledger: which agent, which rule, how long, what it cost.

Not built yet

  • Routing each ask by what every agent declares it can do (a manifest) is planned, not built.
  • The plain-language intent layer is built but switched off.
  • Memory consolidation hasn't been scheduled since May.
