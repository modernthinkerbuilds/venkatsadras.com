Kipchoge

My running coach. Reads every run from the watch, grades it against my own heart-rate cap, and tells me what to run next. Numbers from code, words from the model.

Live on its own door since Nov 1

The problem

The coaching thread I used before this one prescribed a pace from a heart-rate model it had never built, quoted weeks of data it had never pulled, and read a trend into one noisy reading. Fluent and confident, and wrong where it mattered.

Why I have it

A running coach is mostly arithmetic with a voice on top. Kipchoge computes every number in code from the watch data, and the model only explains. It's one of two agents on the platform's harness, the shared loop their answers run through, and the real test of whether Rahat is a platform.

What it does

  • Reads every run from the watch export: first and second half, the ramp, time in band, heart-rate drift, and artifacts like the spike after a stop.
  • Grades an easy run A to D against my own heart-rate cap, with margins and a borderline flag; normalizes pace for heart rate; keeps the trend.
  • On demand: /run, /next and /week call the model once, when I ask. /me, /zones, /goal, /trend, /routes and /run list never do. If the model fails, a template built from the records answers.
  • Says so when a symptom needs a clinician, and flags heat and an erratic heart rate at easy effort.

Where it helped

  • Live on its own door since Nov 1. The evidence so far is a table: 24 checks against the real coaching thread (halves, grades, ramps, sleep, one artifact), 18 match, 6 wait on data the store doesn't hold yet, 0 misses.
  • In ten shadow messages, no number reached a message without a record behind it.
  • The second agent on the shared harness, after Bourdain. Bourdain's 72-case snapshot was unchanged byte for byte after the change.

How it works

The steps, in the order a run meets them. The names are the real components in the code.

  1. Watch exportA run lands, with its heart-rate and distance series.
  2. BridgeKeeps the route and the series the old bridge dropped, in one SQLite file at home.
  3. EngineComputes every number in code: halves, ramp, time in band, drift, grade, normalized pace.
  4. RecordsEach number is a record, with its source, its range and a confidence.
  5. The modelWrites the coaching with a placeholder wherever a number goes. It never writes a digit.
  6. RendererFills each placeholder from its record, in my units.
  7. ChecksA stray digit, a number with no record, a pace outside the model's range: the message isn't sent.
  8. TelegramThe analysis, the next-run card or the week. A template from the records if the model fails.

Not built yet

  • On a clock it sends only two check-ins, Friday and Saturday evenings, from templates. Everything else is on demand; the Sunday review and the analysis when a run lands are built and switched off.
  • Its 22 conversational evals hadn't run when the month's model budget ran out on Oct 25; they're next.
  • The judge grades its answers in shadow, with 8 criteria, and has no vote.
  • Reaching it through Miya is built and switched off. The weekly planner, goal changes, readiness, races and intervals come in later slices.
