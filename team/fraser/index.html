Fraser

Designs workouts.

Live, through Miya · contract since Oct 11

The problem

Getting one good workout out of a general-purpose assistant once took me nine messages and twenty minutes, and the result still had mistakes.

Why I have it

A workout has rules: a warm-up, a cool-down, sensible loads, and no clash with what the gym already programmed. Fraser writes the session, then code checks it before I see it.

What it does

  • Designs a session from my constraints, my week and the gym's plan.
  • Checks it against a 10-point contract in code, with one repair if something fails.
  • If something still fails, the reply names what isn't verified instead of hiding it.

Where it helped

  • The 10-point contract shipped Oct 11, the same day as the nine-message evening that prompted it.
  • Of the 22 harness runs between Oct 4 and 11, three were Fraser designs; the rest were Bourdain answers.

The athlete is me

Fraser designs the sessions I walk into the gym and do, built around what the gym has programmed that week. A plan can read well in a chat window; under the bar is where it gets graded.

How it works

The steps, in the order a message meets them. The names are the real components in the code.

  1. I ask for a workoutOn Telegram, to Miya.
  2. A rule in code claims itA design request is spotted ahead of any numbers lookup.
  3. Fraser's inputsMy constraints, the week, the gym's coming sessions.
  4. The modelWrites the session.
  5. Fraser's contractTen checks in code. One repair if something fails.
  6. Back to meAnything still unverified is named in the reply.

Not built yet

  • Fraser uses the harness's contract pattern but isn't a full harness agent yet.
  • Its model calls aren't cost-recorded yet.
