Rahat, my agent platform

Rahat is the agent platform I built; seven agents run on it. Miya is the one I talk to. The platform owns routing, the harness an agent's answers run through, the evals, the policy checks, the ledger and the spend brake; an agent brings its job. It runs around the clock on a Mac mini at home.

  • 86 real asks in private eval sets

Agents, harness agents and doors counted Nov 1 and tests Oct 17, in the repo; the eval sets (Oct 17) are private, so that one is my count.

Four product decisions

A few weeks after I started talking to Miya, it told me something about myself that had never been true, in a flawless voice. That's when I stopped adding features and started making decisions like these.

DecisionInstead ofWhat it bought
Check every answer in code before it's sentRewriting the prompt ten timesI replayed 126 real messages: replies with the agents' internal notes leaking into them went to zero, and about one reply in twenty had a mistake caught and fixed before it reached me.
Build one shared engine that every new agent plugs intoA new engine for each agentThe running coach plugged in as the second agent, and the food agent's 72 test cases came out exactly the same as before.
Don't let an AI grader decide until it agrees with meTrusting a second AI to grade answers from day oneIt has graded 214 answers with no say yet; it earns a vote after it matches my own judgment on 50 answers, 8 times in 10.
Numbers come from code, not from the AITelling the AI not to make up numbersA message with a number the code didn't compute is never sent. Checked against my old coaching chat: 24 numbers, 18 match, 6 still need data, 0 wrong.

Three loops

Three loops do most of the work: one answers, one tests, one keeps fixed bugs fixed.

LoopWhat runsWhat I measure
The answer loop (the harness)Understand → set the bar → do the work under a brake → check in code → a second AI grades, in shadow → one repair or say what failed → fill numbers from records → keep a recordOutcomes passed and failed per answer, repairs per answer, cost per answer, time to answer
The eval loopEvery model and tool call is recorded against its request; the private test sets (72 food questions, 14 weekend questions) replay with no network and no bill; the judge grades in shadow until it agrees with my labelsPass rate per release; the judge's agreement with my labels; the snapshot diff when the platform changes
The fix loopA failure in real use becomes a regression test; a fix without its own test is refused; the pre-push gate runs the unit, contract and regression layers and the private-words checkTests added per fix (1,877 tests in 219 regression pins, Oct 17); a known-fixed bug coming back blocks the push

How an agent joins the platform

A new agent brings five things: a manifest (its tools, budgets, latency and capabilities), an outcome library (what a good answer must meet: Bourdain 52, Kipchoge 19), a checklist for the judge (21 and 8 criteria), its own shapes (what it reads, what it answers, what counts as evidence) and its tests. The platform brings the loop, the spending brake, the ledger, the judge, the controller and the record.

The gate before it serves: a conformance test, and the first agent's 72-case snapshot unchanged, byte for byte. Kipchoge, the running coach, went through it: the shapes amendment was accepted on Oct 25, and it went live on its own Telegram bot on Nov 1.

Each agent starts on its own door, with its own tests, where its failures can't break anything else; when it passes, it's wired in behind Miya, and Miya stays the one place I ask.

Orchestration is the part I'm least done with. Today sixteen rules in code answer the asks they recognize, most without a model, and Miya's model handles the rest. Routing each ask by what every agent declares it can do is planned, not built.
